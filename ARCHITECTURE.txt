RED SUN — ARCHITECTURE
======================

One shared core, two thin surfaces, one launcher contract.

    Native launcher (macOS .app / Windows .exe / Linux .AppImage)
        |  reads app/launcher/manifest.json, bundles a pinned uv,
        |  installs managed Python 3.12.10 + locked Pillow into app data,
        |  runs app/launcher/bootstrap.py, waits for /health/ready,
        |  then points the browser at the GUI
        v
    red_sun.start  ----------------------------------------------- app/src/red_sun/start.py
        binds 127.0.0.1 (OS-chosen port), publishes the URL, serves forever
        v
    red_sun.server  (stdlib http.server, plain HTML forms, no JS) -- app/src/red_sun/server.py
        GET  /                    the form (restored from config/settings.json)
        POST /choose              save the form, show the OS folder/file dialog (osascript / PowerShell /
                                  zenity), save the answer, 303 back to the form
        POST /jobs                save the form, validate, create <source>/red-sun-run-NNN, start the batch thread
        GET  /jobs/<id>           progress (<meta refresh> + <progress>) or results
        GET  /jobs/<id>/out/n     one output file; ?crop=1 = unscaled 1:1 centre crop
        GET  /jobs/<id>/view/n    the file at natural size with nearest-neighbour rendering
        POST /jobs/<id>/reveal    open the run folder in Finder/Explorer/xdg-open (the only non-GUI action)
        POST /quit                clean shutdown
        GET  /health/ready        readiness for the launcher
        v
    red_sun.core  (pure Pillow, no I/O framework) ----------------- app/src/red_sun/core.py
        Settings -> process(image) -> Processed(image, mode, colors, factor)
        collect_files / next_run_dir / run_batch(files, out_dir, settings, progress)
        ^
    red_sun.__main__  CLI: python -m red_sun <file-or-folder> [...] -- same core, same options

PIPELINE (core.process) — the Photoshop "Indexed Color / Bitmap" recipe, at native resolution
-----------------------
    1. flatten: EXIF rotate, composite transparency onto the matte, RGB
    2. optional pixel grid: ONE Lanczos downscale, only when a grid width is given (default: none)
    3. optional despeckle: 3x3 median (default off)
    4. optional sharpen: unsharp mask r=1, 150%, threshold 2 (default on) — shortens soft edges before the snap
    5. color:  optional fixed 1.3x contrast (hue-safe)
               palette = adaptive median-cut N (computed without dither) | MS Paint 28 | Windows 16 | web-safe 216
               dither  = none | diffusion (Floyd–Steinberg) | pattern (8x8 Bayer field added, then plain snap)
                         | noise (Gaussian field added, then plain snap)
               -> quantize to the exact palette (mode P)
       bw:     optional autocontrast -> threshold (Otsu | manual; 128 = Photoshop 50%) with the same dither choices
               -> mode 1
    6. integer_upscale: NEAREST by ceil(min_output_width / width), never less than 1 -> every block one flat colour
    7. save indexed PNG / BMP / GIF

    Invariant: after step 2 nothing is resampled. Every output pixel is one exact palette colour and every
    edge is a single-pixel step (or a dither texture made of exact colours). Output size is source size x factor.

SECURITY MODEL (local app)
--------------------------
    - Server binds 127.0.0.1 only; port chosen by the OS (or GOOSNAV_PORT_PREFERENCE / RED_SUN_PORT).
    - Every POST needs the per-launch session token (hidden form field) AND a same-origin check
      (Sec-Fetch-Site, else Origin/Referer vs Host). A web page in another tab cannot drive the app.
    - The OS dialog is a child process with explicit argv (osascript -e <script> / powershell -Command / zenity);
      the chosen path is only ever used to read images and create the run folder. The server never serves a
      user-supplied path as a file; outputs are served by job id + index only.
    - settings.json holds only known form keys (the session token is never persisted).
    - Subprocess (reveal) gets explicit argv; nothing is ever passed through a shell. All rendered text is HTML-escaped.
    - No secrets, no network calls, no telemetry. Source images are never modified.

DATA LOCATIONS
--------------
    Outputs:          <folder you processed>/red-sun-run-NNN/ (+ settings.json), or the chosen output folder / --out
    Settings:         GOOSNAV_CONFIG_DIR/settings.json under the launcher; otherwise ~/Library/Application Support/Red Sun/config,
                      %APPDATA%\Red Sun, or $XDG_CONFIG_HOME/red-sun
    Launcher runtime: macOS ~/Library/Application Support/Red Sun, Windows %LOCALAPPDATA%\Red Sun,
                      Linux ~/.local/share/Red Sun  (python/, runtimes/, cache/, logs/, runtime/)
    Source checkout:  no writes except an optional .venv/ created by run.sh without uv.

REPOSITORY MAP
--------------
    app/                    the M1a payload; launchers only ever touch this directory
      pyproject.toml        Pillow pinned, no-build, six required OS/arch environments; uv.lock committed
      src/red_sun/          core.py, server.py, start.py, __main__.py
      static/               style.css (element selectors only: Helvetica bold caps titles, Times body), icon.png, favicon.ico
      launcher/             manifest.json, bootstrap.py, checksums.sha256, tools/<os-arch>/uv (downloaded)
    packaging/              build-host only, never shipped inside app/
      launcher/             vendored Goosnav M1a supervisor (Go) + build/fetch/package scripts
      make_icon.py          pixel-art sun -> AppIcon.png/.ico/.icns + app/static icons
      build_release.py      icons -> uv tools -> go test -> images this host can build -> ZIP
      release/README.txt    the customer-facing readme placed at the ZIP root
    tests/                  test_core.py, test_server.py (pytest), smoke.py (real HTTP end-to-end)
    run.sh / run.command / run.ps1   source-checkout launchers (uv, or python3 + venv)

WHY THESE CHOICES
-----------------
    native resolution, not a pixel grid:  downsampling first turns every edge into a ramp of intermediate palette
        colours; snapping every source pixel keeps edges one pixel wide, exactly like Photoshop's Indexed Color.
        The grid remains an explicit option for the chunky retro look.
    stdlib http.server, not FastAPI:  one dependency (Pillow) means the lock resolves for all six targets with
        prebuilt wheels and first launch downloads ~20 MB. Swap server.py for a framework if an API is ever needed.
    zero JavaScript, the system's own dialogs:  every action is a form POST; Choose folder… runs the operating
        system's standard folder panel (the one thing worth leaving the page for) and comes back with a real
        path. Works with CSS and JS off. No Tk, no in-page file manager.
    run folders next to the pictures:  results are where the user already is; each batch is reproducible from its
        settings.json and never overwrites a previous run; recursive scans skip run folders.
    integer upscale only:  a "poster" is the same indexed image at 2x or 5x; no resampling, no new colours.
